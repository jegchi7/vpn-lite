# Зарубежный вход с российским выходом · CHIMERA 1.2

Этот вариант размещает клиентский VPN, панель и бота на зарубежном сервере.
На русском сервере нужен межсерверный выход. Оба сервера участвуют в работе,
но пользователь подключается только к зарубежному адресу.

| Назначение по политике CHIMERA | Маршрут | IP, который видит сайт |
|---|---|---|
| Российские сервисы и IP из списков, ручное RU-правило | Клиент → зарубежный вход → защищённый канал → RU → сайт | Российский сервер |
| Остальные назначения, ручное FOREIGN-правило | Клиент → зарубежный вход → сайт | Зарубежный сервер |
| Служебные/приватные адреса и IPv6 | Запрет | Соединение не устанавливается |

Списки и ручные правила классифицируют назначения тем же алгоритмом, что в
обычном режиме. Это не обещание автоматически распознать любой российский
сервис: неизвестные имена по-прежнему относятся к FOREIGN, даже если IP в RU.

## Два защищённых пути

Зарубежный вход подключается к RU через VLESS REALITY/Vision по TCP и резервный
Hysteria2/Salamander по UDP. Выбор пути автоматический или ручной из панели.
При отказе обоих путей российская ветка закрывается; запасного выхода этой
ветки с зарубежного IP нет. Зарубежная ветка продолжает работать напрямую.

RU DNS-запросы идут через защищённый путь в RU. Зарубежный DNS работает локально
на зарубежном входе. Начальное разрешение REALITY-handshake на входе не зависит
от RU-пути. На RU-выходе имена разрешаются российским DNS из setup.

AWG и пользовательский VLESS используют одну политику. Default route хоста,
SSH и системный трафик не переносятся в туннель. Для AWG остаётся отдельная
таблица с unreachable default; общего MASQUERADE нет.

## Требования

- Два отдельных VPS с публичными IPv4. Для финальной чистой установки на обоих
  используйте **Ubuntu Server 26.04 LTS, amd64/x86_64** (26.04.1 LTS, если такой
  образ предлагает провайдер), обычный Server или Minimal. Также поддерживается
  Ubuntu 24.04 LTS.
- Домен панели указывает на **зарубежный вход**; доступны TCP/80 для ACME,
  порт панели, клиентский TCP/443 и AWG UDP/443.
- На RU-выходе открываются межсерверные порты только с зарубежного IPv4.
- Нативный установщик не принимает хост с активным Docker/UFW/чужим firewall.
  Их службы и правила он не удаляет.

Режим foreign compat на Ubuntu 20.04 предназначен для облегчённого зарубежного
relay обычной схемы. Он не устанавливает полный вход, панель и бота. Существующий
сервер Ubuntu 20.04 + Docker нельзя превратить в зарубежный вход запуском этой
инструкции; нужен подходящий отдельный хост или заранее подготовленная ОС.

## Настройка

В новом распакованном релизе создайте один setup.toml для обоих серверов:

```bash
chmod +x scripts/*.sh
python3 scripts/init-config.py \
  --entry foreign \
  --ru RU_PUBLIC_IPV4 \
  --foreign FOREIGN_PUBLIC_IPV4 \
  --domain vpn.example.com \
  --email owner@example.com \
  --output setup.toml
```

Подставьте свои адреса и домен. `--ru` всегда означает физический российский IP,
`--foreign` — физический зарубежный IP; переставлять их местами не нужно.
Генератор выставит `deployment.entry = "foreign"` и прямой маршрут для бота.
Без `--entry` сохраняется прежняя схема с RU-входом.

В разделе `[foreign]` поле `ipv4` остаётся зарубежным адресом, а `reality_port`,
`hysteria_port`, `server_name`, `tls_server_name` — параметры межсерверного
выхода. В этой схеме они применяются к RU. Название раздела сохраняется для
совместимости существующих setup. Uplink определяется отдельно на каждом хосте.

## 1. Российский выход

Скопируйте релиз и setup.toml на **свободный RU-хост**, затем:

```bash
./scripts/install-relay.sh --setup /root/setup.toml
```

Установщик настроит два транспорта и предложит пароль для пакета сопряжения.
Пакет `/root/ruvpn-pair.ruvpn` схемы 2 привязан к выбранному зарубежному входу.
Пользовательская БД, панель, AWG и бот на RU-выходе не создаются.

После проверки сохранённого SSH-доступа, в интервал из вывода установщика:

```bash
/opt/ruvpn/current/scripts/configure.sh --confirm-network
```

Через свой компьютер передайте пакет на зарубежный вход:

```bash
scp root@RU_PUBLIC_IPV4:/root/ruvpn-pair.ruvpn .
scp ruvpn-pair.ruvpn root@FOREIGN_PUBLIC_IPV4:/root/
```

Пароль передаётся отдельно от файла; не печатайте содержимое пакета в чат.

## 2. Зарубежный вход

На **свободном зарубежном хосте** с тем же setup.toml:

```bash
./scripts/install-entry.sh --setup /root/setup.toml --pair /root/ruvpn-pair.ruvpn
```

После проверки SSH подтвердите сеть на этом хосте:

```bash
/opt/ruvpn/current/scripts/configure.sh --confirm-network
/opt/ruvpn/current/scripts/status.sh
```

Панель доступна по указанному домену/порту на зарубежном входе. Первый логин
и пароль, если они создавались, находятся в `/root/ruvpn-owner.txt` именно там.
Пользовательские AWG/Amnezia/VLESS профили содержат только адрес входа,
не адрес или credentials RU-выхода.

## Telegram-бот

На зарубежном входе:

```bash
/opt/ruvpn/current/scripts/configure.sh --set-bot
```

Введите токен из BotFather и username. В панели откройте «Учётная запись →
Telegram-бот → Привязать» и запустите бота по одноразовой ссылке.

Работают создание устройств, все форматы профилей, отзыв, удаление отозванных,
инструкции, экран сети, приглашения, восстановление и блокировка пользователей
владельцем. «Назад» ведёт к родительскому экрану, «Главная» отменяет ввод.
При зарубежном входе обращения бота идут напрямую с зарубежного хоста и не
зависят от RU-пути, в том числе при старом `telegram.route = "foreign"`.

## Существующая установка

CHIMERA 1.2 обновляет обычный RU-вход без смены географии или credentials.
Пустой/отсутствующий `[deployment]` означает `entry = "ru"`.

Смена `deployment.entry` в уже установленном setup отклоняется до изменения
сети. Переворот рабочих серверов требует отдельной миграции ролей, ключей,
пакетов, домена и пользовательских профилей; простой кнопки переключения нет.
Откат версии зарубежного входа на релиз без поддержки этой схемы блокируется.

Служебные пути `/opt/ruvpn`, `/etc/ruvpn`, unit-имена и внутренние маркеры роли
`ru` (полный вход) / `foreign` (межсерверный выход) сохранены. Их имена не задают
географию в версии 1.2: география определяется `deployment.entry`.
