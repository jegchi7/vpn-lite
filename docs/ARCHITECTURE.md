# Устройство продукта

## Data plane

RU: AmneziaWG 3.1 userspace → awg0 → таблица 51823 → ruvpn-tun → sing-box.
VLESS REALITY завершается в том же sing-box. Оба входа используют одну функцию
компиляции политики в gateway/compiler.py.

Правила в порядке применения: служебная изоляция, ручные назначения с явным
приоритетом, RU-services, известное прочее имя → FOREIGN, неизвестное имя и
RU-IP → direct, остальное → FOREIGN. IPv6 отклоняется. DNS TCP/UDP 53
перехватывается шлюзом. Явно разрешённые владельцем network.allowed_services
содержат IP/порт/протокол; по умолчанию список пуст. Адреса самого RU,
loopback, link-local и другие служебные назначения такими сервисами не становятся.

AWG forwarding допускается только между awg0 и ruvpn-tun. MASQUERADE для
подсети отсутствует. При остановке ядра маршрут в TUN исчезает, но в таблице
остаётся unreachable default. Нельзя провалиться в default route хоста.
Сокеты direct создаёт sing-box после классификации; его output дополнительно
ограничен nftables по UID. Это также закрывает DNS-rebinding к приватным адресам.

Policy rule ограничен iif awg0; хостовые SSH/apt/время идут по прежней основной
таблице. Все межсерверные соединения и direct привязаны к uplink. auto_route
на серверном TUN выключен. Интерфейсы VPN не открывают SSH и панель.
Обычные сообщения ICMP/IPv6 ICMP на сервере не блокируются; сквозной ICMP
через прокси не входит в контракт продукта.

Foreign: только sing-box с входами VLESS REALITY/TCP и Hysteria2/UDP.
Они используют отдельные UUID, ключи, short ID, пароли. Firewall допускает
эти порты с RU IPv4. Приватные и служебные назначения на выходе закрыты.
Foreign не хранит конечные пользовательские UUID или AWG private keys.

Для foreign на Ubuntu 20.04 рядом с существующей Amnezia предусмотрен
[режим совместимости](FOREIGN-COMPAT.md). Он использует тот же foreign_config
и формат сопряжения, но отдельные пути /etc/ruvpn-foreign и службу
ruvpn-foreign. Только этот режим допускает существующий Docker: его firewall
ограничивается новыми портами INPUT и выделенным UID в OUTPUT iptables-legacy,
сохраняя FORWARD/NAT существующего VPN. Бинарник извлекается из закреплённого
официального образа; работающей контейнерной службы для него не создаётся.

## Имена и DNS

Клиентские A-запросы получают FakeIP 198.18.0.0/15. Для каждого имени выделяется
собственное синтетическое назначение, поэтому два домена на одном CDN IP не
затирают друг друга. Соответствия сохраняются ядром на диске между рестартами.
Это техническое сопоставление FakeIP, а не журнал посещений; cache.db содержит
эти имена до вытеснения и не предоставляется пользователям.

При установлении RU_DIRECT-соединения настоящее имя разрешается RU DNS.
Имена в FOREIGN передаются через защищённый прокси; на foreign они разрешаются
его резолвером. Прочие DNS-запросы управляемого клиента, кроме AAAA, идут через
RU/foreign DNS по доменным правилам. Foreign DNS использует DoH с detour foreign;
RU fallback для него отсутствует. AAAA возвращает пустой NOERROR.

Sniff применяется, когда ещё нет известного имени; он извлекает HTTP Host,
TLS SNI, QUIC и DNS без MITM. FakeIP/явное имя VLESS сохраняют назначение;
ненадёжный reverse mapping общего IP не используется. TTL реальных ответов
обрабатывает DNS-кэш ядра. DoH/DoT/ECH приложений могут оставить только IP-ветку.
Нельзя гарантировать достоверность имени, которое скрыло само приложение.

Bootstrap REALITY handshake использует отдельный RU DNS/direct. Endpoint
foreign задаётся IPv4, TLS server name отдельно; рекурсии через TUN нет.

## Пути

Основной — VLESS REALITY + Vision + uTLS chrome. Резервный — Hysteria2 с
Salamander и отдельным доверенным сертификатом. При выпуске foreign создаёт
самоподписанный ECDSA сертификат на 365 дней. RU доверяет именно этому PEM
с указанным SAN; insecure не включается. Ротация явно перевыпускает пакет.

Selector содержит primary, backup, closed; direct в него не входит. closed —
настоящий block outbound выбранной версии sing-box, без сетевого назначения.
Локальные HTTP proxy на 10081/10082 направляют эксплуатационные запросы строго
в соответствующий транспорт, 10083 — в выбранный foreign. Они слушают loopback
и требуют отдельную авторизацию. Clash API слушает loopback и требует секрет.
Управление им проходит только через helper.

Контроллер делает HTTPS-запросы к двум адресам с ожидаемым 204. Состояния каждого
назначения и последовательные ошибки учитываются отдельно. Хотя бы один успешный
ответ означает успех пути; один сломавшийся внешний адрес не выключает транспорт.
По умолчанию: 30 секунд между циклами, 3 неудачи подряд, пауза переключений
120 секунд, возврат к основному после 5 успехов. Оба отказали → closed.
Закрытие при полном отказе немедленное; восстановление Auto учитывает паузу.
Принудительный режим сохраняет выбранный защищённый путь даже при его отказе.
Пути можно отключать в setup; их статус будет disabled.

Панель, монитор и бот находятся в одном непривилегированном процессе. При его
остановке сохраняется текущий data plane и выбранный путь; автоматический
контроль возобновится после запуска ruvpn-panel. Это намеренно небольшой стек
для частного использования, без обязательного брокера или внешней БД.

## Control plane

FastAPI + Jinja2 + SQLite, один worker. Cookie-сессии серверные; в БД только
хеш cookie/token. Пароли — Argon2id. CSRF есть на изменениях, приглашения
ограничены временем и используются один раз. Есть ограничения попыток входа.
Ссылки и профили не попадают в access logs. Управляющие события ограничены
последними 2 000 записями; служебные журналы обслуживает journald.

Таблицы: users, devices, credentials, invitations, route_overrides, gateways,
transports, applied_revisions, sessions, downloads, settings, events, throttle.
У устройства независимые AWG key/PSK и VLESS UUID. Credentials в SQLite
зашифрованы Fernet, ключ находится в /etc/ruvpn/vault.key вне базы.

Control.serialize использует flock на диске и SQL BEGIN IMMEDIATE. Запрос
создания имеет идемпотентный ключ и дополнительную уникальность активного имени
внутри пользователя. После мутации создаётся pending revision. Helper строит
конфигурацию, ядро проверяет допустимость, затем применяются AWG peer-set и
контролируемый restart sing-box. Только после ответа helper состояние становится
applied и профиль доступен. Ошибка возвращает failed и предыдущую конфигурацию.

Отзыв удаляет peer и UUID, инвалидирует ссылки и закрывает VLESS-сессии рестартом.
Если отзыв failed, старый профиль ещё может действовать — интерфейс сообщает
об этом. Удаление ссылки не подменяет серверный отзыв.

RPC — Unix socket 0660 с проверкой SO_PEERCRED. Разрешены только apply, select,
status, explain, обновление и откат списков. Пути, shell и произвольные команды
в запросах не принимаются. Snapshot проверяется до привилегированных действий.
Код, venv, root-секреты и конфигурации ядра недоступны панели на запись.

## Ревизии и расширение

Конфиги сохраняются атомарно; helper хранит 10 последних applied snapshots.
Правила списков ссылаются на неизменяемые версии каталогов. Обновление источника
не чаще раза в сутки, временная недоступность не удаляет предыдущую версию.
Откат списков не переписывает ручные назначения.

Gateway и Transport отделены от User/Device/Credential. Добавление второго
foreign потребует расширить выбор транспортов/настройки, но не перевыпускать
пользовательские профили или менять личный кабинет. В этом выпуске развёртывается
один foreign с двумя транспортами; второго узла и балансировки нет.

Сетевой откат восстанавливает предыдущие настройки и компилирует актуальные
желаемые credentials, поэтому отзыв устройства не отменяется из старого файла.
Зашифрованное восстановление копии — отдельная операция: оно сознательно
возвращает состояние пользователей и ключей на дату копии.
