# CHIMERA · 1.2.0

Частный VPN для владельца и близких: AWG 3.1 и VLESS REALITY принимают
подключения на RU. Единая политика выпускает российские сервисы напрямую,
остальной трафик — через foreign. Основной межсерверный путь — VLESS REALITY,
резервный — Hysteria2 с Salamander и проверкой сертификата.

В поставке: серверное приложение, тёмная мобильная веб-панель, Telegram-бот,
выдача/отзыв профилей, установщики, приоритетное резервирование, обновление,
откат и зашифрованные резервные копии. Исходники и инструкции самодостаточны
как проект; зависимости загружаются установщиком либо заранее.

Владелец подтвердил работу AWG и VLESS через Happ/v2rayNG на Android
19 октября 2026 года. Версия 1.2 включает панель и навигацию бота из 1.1;
предварительно устанавливать 1.1 не нужно. Автотестов и тестовой CI нет по
исходному заданию.

## Где размещается вход

По умолчанию клиенты подключаются к RU, зарубежные назначения идут через foreign.
Добавлен отдельный режим **зарубежного входа**: клиенты, панель и Telegram-бот
на зарубежном узле; российские сервисы отправляются по защищённому каналу на RU,
остальное выходит прямо с зарубежного входа. При отказе RU-пути блокируется
только российская ветка.

Генератор: `scripts/init-config.py --entry foreign ...`. Развёртывание выполняют
`scripts/install-relay.sh` на RU и `scripts/install-entry.sh` на зарубежном
сервере. Полная инструкция и требования: [FOREIGN-ENTRY.md](docs/FOREIGN-ENTRY.md).
Параметр не переключает существующие рабочие серверы на лету.

## Панели CHIMERA

Личный кабинет и панель владельца реализованы на Svelte 5. Интерфейс полностью
на русском, шрифт Manrope с кириллицей поставляется локально. Обычный пароль —
от 8 символов, пароль владельца — от 12. Доступны ключи входа WebAuthn,
восстановление пароля через приглашение владельца и запоминание входа на 7 дней.

Владелец видит трафик ядра, соединения, CPU/RAM входа, историю за 24 часа/7/30 дней
и результаты HTTPS-проверок обоих межсерверных путей. Пользователь видит AWG-счётчики
только своих устройств; индивидуальная статистика VLESS не заявляется. Счётчики
AWG сбрасываются при пересоздании интерфейса/peer. Пропуски измерений показываются
как отсутствие данных. Квот трафика и ограничения скорости нет.

Отозванные после успешного применения устройства можно удалить по одному или
очистить списком. Действующие и неуспешно отозванные профили не удаляются.
Нативный ключ Amnezia `vpn://` и VLESS URI импортируются с именем
`CHIMERA · название устройства`; старый формат AWG `.conf` также сохранён.
Safari ClientHello в VLESS выдаётся как `hellosafari_16_0`.

Собранные JS/CSS входят в `static/panel`, Node.js на VPS не нужен. Для изменения
интерфейса в исходниках:

```bash
cd web
npm ci
npm run check
npm run build
```

Граф и правила переходов бота: [BOT-NAVIGATION.md](docs/BOT-NAVIGATION.md).
Описание изменений и обновления: [CHIMERA-1.1.md](docs/CHIMERA-1.1.md).

## Перед установкой

Для финальной чистой установки рекомендуем на обоих VPS **Ubuntu Server 26.04
LTS, amd64/x86_64** (26.04.1 LTS, если доступен такой образ), Server или Minimal.
Следующие пошаговые разделы описывают RU-вход; для зарубежного входа используйте
[отдельную инструкцию](docs/FOREIGN-ENTRY.md).

**Foreign на Ubuntu 20.04 с существующим Docker/Amnezia:** используйте отдельный
[режим совместимости](docs/FOREIGN-COMPAT.md). Он сохраняет ОС, системный Python
и текущий VPN. Описанная ниже нативная установка рассчитана на свободные хосты
Ubuntu 24.04/26.04; её требования не нужно обходить удалением проверок.

- Два отдельных VPS с публичными IPv4, Ubuntu 24.04 или 26.04 LTS,
  amd64/arm64, systemd и /dev/net/tun. Ориентир — 1–2 GB RAM на узел.
- SSH-доступ владельца. Скрипты сохраняют способ входа и не отключают пароль.
  Для постоянной эксплуатации используйте уже настроенные SSH-ключи.
- Домен/hostname панели с A-записью на вход (по умолчанию RU). Для HTTP-01 TCP/80 должен быть
  доступен из интернета. Панель слушает HTTPS TCP/8443; TCP/443 занят VLESS.
- На хостах не должны одновременно управлять сетью UFW, firewalld, Docker
  или чужие nftables-таблицы. При таком конфликте установка останавливается.
  Посторонние службы не удаляются. Разрешённые дополнительные порты задаются
  в extra_tcp_ports / extra_udp_ports.
- Для обычной установки доступны репозитории Ubuntu, PyPI, GitHub и Go.
  Если GitHub недоступен с VPS, см. «Предварительная загрузка» ниже.

## Один конфиг для обоих серверов

Распакуйте релиз. Создайте файл с четырьмя своими значениями:

```bash
chmod +x scripts/*.sh
python3 scripts/init-config.py --ru RU_IPV4 --foreign FOREIGN_IPV4 \
  --domain vpn.example.com --email owner@example.com --output setup.toml
```

Замените RU_IPV4/FOREIGN_IPV4 реальными адресами, домен и email — своими.
При нестандартном SSH-порте измените network.ssh_port. Uplink по умолчанию
определяется на каждом VPS автоматически. management_cidrs допускает текущий
SSH-адрес; начальное значение сохраняет доступ с любых адресов.

Конфиг не содержит секретов. Приватные ключи создаются отдельно на серверах.
Скопируйте архив/распакованный каталог и одинаковый setup.toml на оба VPS.
В командах ниже он лежит в /root/setup.toml. Если сохранили его рядом с
проектом на самом VPS, вместо этого пути передавайте --setup ./setup.toml.

## 1. Foreign

Для Ubuntu 20.04 + Docker этот раздел заменяется
[установкой foreign compat](docs/FOREIGN-COMPAT.md). RU устанавливается обычным
способом с полученным зашифрованным пакетом.

Из каталога проекта, от root:

```bash
./scripts/install-foreign.sh --setup /root/setup.toml
```

Установщик поднимет оба транспорта и предложит пароль для зашифрованного
пакета сопряжения. Используйте минимум 16 символов. Пакет появится в
`/root/ruvpn-pair.ruvpn`. Секреты на экране не выводятся.

**В течение 180 секунд после изменения сети сохраните доступ по SSH и
подтвердите его:**

```bash
/opt/ruvpn/current/scripts/configure.sh --confirm-network
```

Без подтверждения сработает автоматический откат. Не откладывайте подтверждение
до настройки второго сервера. Если лимита времени мало, заранее увеличьте
network.rollback_seconds, максимум — 600 секунд.
Если перезагрузить VPS до подтверждения, на старте восстановится предыдущая
сеть, а VPN останется закрыт до повторного configure/install с вашим setup.

Передайте пакет на RU через свой компьютер/SSH, например с компьютера:

```bash
scp root@FOREIGN_IPV4:/root/ruvpn-pair.ruvpn .
scp ruvpn-pair.ruvpn root@RU_IPV4:/root/
```

Пароль передайте себе отдельно от файла. После успешного импорта копию пакета
на foreign и компьютере можно удалить; на RU установщик удалит её сам.

## 2. RU

На RU, из распакованного проекта, от root:

```bash
./scripts/install-ru.sh --setup /root/setup.toml --pair /root/ruvpn-pair.ruvpn
/opt/ruvpn/current/scripts/configure.sh --confirm-network
```

При импорте введите пароль пакета. Установщик настраивает AWG, sing-box/TUN,
firewall, policy routing, базу, helper, панель и HTTPS. Foreign допускает
межсерверные соединения только с ru_ipv4. Устройство конечного пользователя
не получает адрес или секрет foreign.

Откройте `https://ВАШ-ДОМЕН:8443`. Первый пароль владельца находится только
на RU в `/root/ruvpn-owner.txt`; логин по умолчанию `owner`. После первого
входа смените пароль в учётной записи и удалите этот временный файл.

В разделе «Управление» создайте пользователя и передайте ему логин и одноразовое
приглашение. Пользователь задаст пароль, добавит устройство и скачает ключ Amnezia,
VLESS URI/QR либо JSON для sing-box. Один и тот же профиль можно получать
повторно без замены ключей. Ротация ключей — отдельная кнопка.

## Telegram

На входном узле, где размещена панель:

```bash
/opt/ruvpn/current/scripts/configure.sh --set-bot
```

Введите токен из BotFather и username бота. Токен хранится вне Git. Пользователь
открывает «Учётная запись → Telegram-бот → Привязать». Ссылка одноразовая,
действует час и привязывает числовой Telegram ID в личном чате.

Бот показывает устройства и состояние маршрутов, создаёт новое, выдаёт профиль, отзывает доступ
и удаляет успешно отозванные профили. Экраны имеют возврат и главное меню;
ввод названия отменяется при переходе. Владелец управляет пользователями
и приглашениями через кнопки.
По умолчанию выдаётся одноразовая HTTPS-ссылка на 5 минут с кнопкой скачивания;
предпросмотр ссылки её не расходует. Файл в Telegram отправляется только по
отдельной кнопке пользователя. QR в чат тоже требует явного выбора. Владелец
также получает команды `/invite login` и `/block login` с подтверждением блокировки,
уведомления о смене пути и длительном отказе.

Исходящий маршрут бота задаётся telegram.route: foreign или direct. Он не меняет
маршруты других служб хоста. При потере Telegram панель работает самостоятельно.

## Обычные команды

Все команды ниже выполняются на соответствующем VPS от root:

```bash
# Понятный статус без ключей и профилей
/opt/ruvpn/current/scripts/status.sh

# Изменить настройки; при сетевом изменении снова подтвердить доступ
/opt/ruvpn/current/scripts/configure.sh --setup /root/setup.toml
/opt/ruvpn/current/scripts/configure.sh --confirm-network

# Немедленно вернуть предыдущее ожидающее изменение сети
/opt/ruvpn/current/scripts/configure.sh --rollback-network

# Подключить перевыпущенный foreign-пакет без изменения устройств
/opt/ruvpn/current/scripts/pair.sh /root/ruvpn-pair.ruvpn

# Зашифрованная копия: БД, конфигурации, необходимые ключи
/opt/ruvpn/current/scripts/backup.sh /root/ruvpn-backup.ruvpn

# Восстановление на том же сетевом окружении; затем подтвердить сеть
/opt/ruvpn/current/scripts/restore.sh /root/ruvpn-backup.ruvpn
/opt/ruvpn/current/scripts/configure.sh --confirm-network

# Обновление из распакованного следующего релиза
/opt/ruvpn/current/scripts/update.sh /root/ru-foreign-vpn-NEXT
/opt/ruvpn/current/scripts/configure.sh --confirm-network

# Предыдущий установленный релиз с текущими желаемыми отзывами устройств
/opt/ruvpn/current/scripts/rollback.sh
/opt/ruvpn/current/scripts/configure.sh --confirm-network
```

При ошибке применения новое устройство не получает профиль. Для отзыва ошибка
означает, что старые ключи ещё могут работать: владелец устраняет причину и
нажимает «Повторить применение». Успешный отзыв удаляет AWG peer и VLESS UUID;
VLESS-сессии завершаются контролируемым перезапуском ядра.

Смена конфигурации может кратко прервать другие VLESS-сессии. AWG peer-set
обновляется через syncconf без пересоздания ключей остальных устройств.

## Предварительная загрузка

На отдельном Linux/WSL компьютере нужной архитектуры с Python той же minor-версии:

```bash
./scripts/prepare-offline.sh --arch amd64
```

Передайте **весь каталог с vendor/** на VPS. Файлы upstream проверяются по
SHA256, AWG собирается заранее, Python wheels устанавливаются без PyPI.
Зависимости Ubuntu должны быть доступны или установлены заранее; для второго
варианта используйте `--skip-apt`. Такая установка не зависит от доступа VPS
к GitHub. Подробности — [vendor/README.md](vendor/README.md).

## Границы выпуска

- IPv4-выход. IPv6 профиля захватывается и отклоняется; у VLESS URI настройки
  полного TUN, IPv6 и kill switch включаются в самом приложении. Один браузерный
  прокси не покрывает весь компьютер. См. [клиенты](docs/CLIENTS.md).
- RU-services — управляемая политика, RU-IP — делегирование диапазонов RIR,
  а не безошибочная геолокация. Поставляются 133 доменных suffix и 8 663 IPv4
  prefix. Ручные правила выше списков; служебные запреты выше ручных правил.
- FakeIP сохраняет соответствие имени и соединения без неоднозначного reverse
  DNS на общих CDN. Обычный DNS внутри VPN управляется шлюзом. Пользовательский
  DoH/DoT и ECH могут скрыть имя; тогда работает IP-ветка.
- Панель и служебные адреса закрыты из пользовательского туннеля. Для панели
  и одноразовых ссылок может потребоваться временно отключить VPN на устройстве.
- При отказе обоих путей межсерверная ветка блокируется, локальная сохраняется:
  для RU-входа закрывается FOREIGN, для зарубежного входа — RU_DIRECT. Два
  транспорта на одном IP не защищают от блокировки самого IP или аварии VPS.
- ICMP через прокси и бесшовное сохранение TCP при смене пути не обещаются.
- REALITY/Salamander не гарантируют невидимость DPI или обход любой блокировки.
- Восстановление копии возвращает пользователей и отзывы на дату копии.
  Пароль восстановления храните отдельно. Перенос на другой адрес/uplink
  требует нового setup и сопряжения.
